# Test-Driven Development (TDD) Discipline & Code Quality

## 1. Red-Green-Refactor Cycle
Every feature and bug fix MUST follow Kent Beck's TDD cycle:
1. **Red**: Write a failing unit or integration test defining the desired behavior. Run the test to confirm it fails for the expected reason.
2. **Green**: Write the minimal code necessary to make the test pass. Verify the test passes.
3. **Refactor**: Clean up the implementation, improve readability, remove duplication, and ensure zero regressions.

## 2. Zero AI Comment Noise
- Code comments must explain **WHY**, never **WHAT**.
- NEVER add AI planning metadata, ticket references, or workflow tags in source code comments (e.g. `# Story: 1-2`, `# Epic: Auth`, `# Generated by AI`).
- Maintain clean, human-quality production code.

## 3. Atomic Git Commits
- Each completed story must result in a clean, self-contained git commit.
- Commit message format: `feat(<component>): <actionable description>` or `fix(<component>): <actionable description>`.
- Never commit broken tests or unverified code.
